# SafeCheck API Contract (v1)

Status: Frozen for Phase 3+ development. Any change here must be a deliberate, documented decision — not a silent drift between backend and frontend.

## Endpoint: POST /v1/check

Analyzes a single piece of user-submitted content: raw text, a URL, or an email.

### Request

```json
{
  "source_type": "TEXT",
  "payload": {
    "text": "Congratulations! You have won a lottery. Pay Rs 5000 to claim your prize."
  }
}
```

```json
{
  "source_type": "URL",
  "payload": {
    "url": "https://example-bank-verify.com/login"
  }
}
```

```json
{
  "source_type": "EMAIL",
  "payload": {
    "sender": "support@example.com",
    "subject": "Your account will be suspended",
    "body": "Click here immediately to verify your account: https://example.com/verify",
    "attachments": []
  }
}
```

### Field rules

| Field | Type | Required | Notes |
|---|---|---|---|
| `source_type` | string enum | yes | One of `TEXT`, `URL`, `EMAIL` |
| `payload.text` | string | required for `TEXT` | Non-empty, max 20,000 characters |
| `payload.url` | string | required for `URL` | Must be a syntactically valid URL |
| `payload.sender` | string | required for `EMAIL` | Email address of sender, may be spoofed/unverified |
| `payload.subject` | string | optional for `EMAIL` | Defaults to empty string |
| `payload.body` | string | required for `EMAIL` | Non-empty |
| `payload.attachments` | array | optional for `EMAIL` | Filenames/metadata only in Phase 2; content upload is handled separately in Phase 3+ via `/v1/document` |

### Response (200 OK)

```json
{
  "case_id": "case_8f3b2c1a",
  "source_type": "TEXT",
  "risk": {
    "score": 82,
    "band": "HIGH"
  },
  "evidence": [
    {
      "signal": "URGENT_PAYMENT",
      "category": "rules",
      "points": 20,
      "reason": "The message pressures the user to pay immediately.",
      "source": "rule_engine",
      "confidence": "high",
      "availability": "available",
      "correlationGroup": "CORR_URGENCY",
      "severity": "HIGH"
    },
    {
      "signal": "LOTTERY_OR_PRIZE",
      "category": "rules",
      "points": 25,
      "reason": "The message claims the user won a prize requiring payment to claim.",
      "source": "rule_engine",
      "confidence": "high",
      "availability": "available",
      "correlationGroup": "CORR_LOTTERY",
      "severity": "HIGH"
    }
  ],
  "explanation": {
    "summary": "This message shows strong signs of a lottery/prize scam.",
    "why": [
      "It creates urgency around an unsolicited prize.",
      "It asks for payment before releasing any reward."
    ],
    "next_action": "Do not pay or share personal details. Verify independently before acting.",
    "uncertainty": []
  },
  "safe_actions": [
    "Do not click any links or pay any fee.",
    "Ask a trusted contact to review this message."
  ],
  "created_at": "2026-09-04T10:15:00Z"
}
```

### Response field rules

| Field | Type | Notes |
|---|---|---|
| `case_id` | string | Unique identifier, generated by backend |
| `source_type` | string enum | Echoes the request's `source_type` |
| `risk.score` | integer 0–100 | `score = min(100, Rule_points + URL_points + ML_points)`. Category caps: Rule ≤45, URL ≤35, ML ≤20. Full definition in `docs/scoring-engine.md` |
| `risk.band` | string enum | `LOW` (0–24), `UNCERTAIN` (25–39), `MEDIUM` (40–74), `HIGH` (75–100) — derived, never set independently. Matches the shared Android scoring contract |
| `evidence` | array | Each item must include `signal`, `points`, `reason`, `source`, `confidence`, `availability`, plus `category` (`rules`\|`url`\|`ml`), `correlationGroup`, and `severity` per `docs/scoring-engine.md` |
| `evidence[].availability` | string enum | `available` or `unavailable` — an unavailable provider must contribute 0 points, never treated as malicious |
| `explanation.summary` | string | Plain-language summary, produced by LLM but must not alter `risk.score` |
| `explanation.uncertainty` | array | Notes about unavailable checks or low-confidence findings |
| `safe_actions` | array of strings | User-facing recommended next steps |
| `created_at` | string | ISO 8601 UTC timestamp |

### Error responses

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "payload.text is required for source_type TEXT"
  }
}
```

| HTTP status | Meaning |
|---|---|
| 400 | Invalid or missing fields in the request |
| 422 | `source_type` valid but payload fails schema validation |
| 500 | Unexpected backend error (must not leak stack traces) |
