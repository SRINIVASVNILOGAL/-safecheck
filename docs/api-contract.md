# SafeCheck API Contract (v1)

Status: Frozen for Phase 3+ development. Any change here must be a deliberate, documented decision — not a silent drift between backend and frontend.

## Endpoint: POST /v1/check

Analyzes a single piece of user-submitted content: raw text, a URL, or an email.

### Request

```json
{
  "source_type": "TEXT",
  "payload": {
    "text": "Congratulations! You have won a lottery. Pay Rs 5000 to claim your prize."
  }
}
```

```json
{
  "source_type": "URL",
  "payload": {
    "url": "https://example-bank-verify.com/login"
  }
}
```

```json
{
  "source_type": "EMAIL",
  "payload": {
    "sender": "support@example.com",
    "subject": "Your account will be suspended",
    "body": "Click here immediately to verify your account: https://example.com/verify",
    "attachments": []
  }
}
```

### Field rules

| Field | Type | Required | Notes |
|---|---|---|---|
| `source_type` | string enum | yes | One of `TEXT`, `URL`, `EMAIL` |
| `payload.text` | string | required for `TEXT` | Non-empty, max 20,000 characters |
| `payload.url` | string | required for `URL` | Must be a syntactically valid URL |
| `payload.sender` | string | required for `EMAIL` | Email address of sender, may be spoofed/unverified |
| `payload.subject` | string | optional for `EMAIL` | Defaults to empty string |
| `payload.body` | string | required for `EMAIL` | Non-empty |
| `payload.attachments` | array | optional for `EMAIL` | Filenames/metadata only; actual file content is analyzed via `POST /v1/document` |

Note: `POST /v1/check` handles text-based input only. Document/file input has its own endpoint (`POST /v1/document`) because it requires `multipart/form-data` rather than JSON. Both endpoints return the same response shape.

### Response (200 OK)

```json
{
  "case_id": "case_8f3b2c1a",
  "source_type": "TEXT",
  "risk": {
    "score": 82,
    "band": "HIGH"
  },
  "evidence": [
    {
      "signal": "URGENT_PAYMENT",
      "category": "rules",
      "points": 20,
      "reason": "The message pressures the user to pay immediately.",
      "source": "rule_engine",
      "confidence": "high",
      "availability": "available",
      "correlationGroup": "CORR_URGENCY",
      "severity": "HIGH"
    },
    {
      "signal": "LOTTERY_OR_PRIZE",
      "category": "rules",
      "points": 25,
      "reason": "The message claims the user won a prize requiring payment to claim.",
      "source": "rule_engine",
      "confidence": "high",
      "availability": "available",
      "correlationGroup": "CORR_LOTTERY",
      "severity": "HIGH"
    }
  ],
  "explanation": {
    "summary": "This message shows strong signs of a lottery/prize scam.",
    "why": [
      "It creates urgency around an unsolicited prize.",
      "It asks for payment before releasing any reward."
    ],
    "next_action": "Do not pay or share personal details. Verify independently before acting.",
    "uncertainty": []
  },
  "safe_actions": [
    "Do not click any links or pay any fee.",
    "Ask a trusted contact to review this message."
  ],
  "created_at": "2026-09-04T10:15:00Z"
}
```

### Response field rules

| Field | Type | Notes |
|---|---|---|
| `case_id` | string | Unique identifier, generated by backend |
| `source_type` | string enum | `TEXT`, `URL`, `EMAIL`, or `DOCUMENT`. Echoes the request's `source_type` for `/v1/check`; always `DOCUMENT` for `/v1/document` |
| `risk.score` | integer 0–100 | `score = min(100, Rule_points + URL_points + ML_points)`. Category caps: Rule ≤45, URL ≤35, ML ≤20. Full definition in `docs/scoring-engine.md` |
| `risk.band` | string enum | `LOW` (0–24), `UNCERTAIN` (25–39), `MEDIUM` (40–74), `HIGH` (75–100) — derived, never set independently. Matches the shared Android scoring contract |
| `evidence` | array | Each item must include `signal`, `points`, `reason`, `source`, `confidence`, `availability`, plus `category` (`rules`\|`url`\|`ml`), `correlationGroup`, and `severity` per `docs/scoring-engine.md` |
| `evidence[].availability` | string enum | `available` or `unavailable` — an unavailable provider must contribute 0 points, never treated as malicious |
| `explanation.summary` | string | Plain-language summary, produced by LLM but must not alter `risk.score` |
| `explanation.uncertainty` | array | Notes about unavailable checks or low-confidence findings |
| `safe_actions` | array of strings | User-facing recommended next steps |
| `created_at` | string | ISO 8601 UTC timestamp |

### Error responses

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "payload.text is required for source_type TEXT"
  }
}
```

| HTTP status | Meaning |
|---|---|
| 400 | Invalid or missing fields in the request |
| 422 | `source_type` valid but payload fails schema validation |
| 500 | Unexpected backend error (must not leak stack traces) |

## Endpoint: POST /v1/document

Analyzes an uploaded document (PDF or image). Uses `multipart/form-data` rather than JSON because it accepts binary file content.

### Request

```http
POST /v1/document
Content-Type: multipart/form-data
```

| Form field | Type | Required | Notes |
|---|---|---|---|
| `file` | file | yes | The document to analyze |

### Accepted file types

| Type | Extension | Extraction method | Requires external binary? |
|---|---|---|---|
| PDF | `.pdf` | Embedded text extraction | No |
| PNG | `.png` | OCR | Yes — Tesseract |
| JPEG | `.jpg`, `.jpeg` | OCR | Yes — Tesseract |

### Limits

| Limit | Value | Rationale |
|---|---|---|
| Max file size | 10 MB | Well above typical documents; prevents memory exhaustion from a single request |
| Max extracted text | 20,000 characters | Matches the `payload.text` limit on `/v1/check`; text beyond this is truncated, and the truncation is reported in `explanation.uncertainty` |

### Response (200 OK)

Identical shape to `POST /v1/check`, with `source_type` always `"DOCUMENT"`.

```json
{
  "case_id": "case_3d9e1f7b",
  "source_type": "DOCUMENT",
  "risk": {
    "score": 45,
    "band": "MEDIUM"
  },
  "evidence": [
    {
      "signal": "ADVANCE_FEE_REQUEST",
      "category": "rules",
      "points": 20,
      "reason": "The document requests an upfront fee to secure an offer or admission.",
      "source": "document_analyzer",
      "confidence": "high",
      "availability": "available",
      "correlationGroup": "CORR_ADVANCE_FEE",
      "severity": "HIGH"
    }
  ],
  "explanation": {
    "summary": "This document shows several signs that may indicate fraud.",
    "why": ["The document requests an upfront fee to secure an offer or admission."],
    "next_action": "Be cautious. Verify this document directly with the organization it claims to be from.",
    "uncertainty": []
  },
  "safe_actions": [
    "Verify the organization through its official website or helpline.",
    "Do not pay any fee before independently confirming the offer is genuine."
  ],
  "created_at": "2026-09-04T15:40:00Z"
}
```

### Extraction failure handling

Text extraction is treated like an external provider: if it cannot be completed, the analysis still returns `200` with `availability="unavailable"` evidence carrying `points=0`, never a crash and never a false "clean" result.

| Situation | Behavior |
|---|---|
| PDF has no extractable text (e.g. scanned image inside a PDF) | `TEXT_EXTRACTION` evidence, `availability="unavailable"`, `points=0` |
| Image uploaded but Tesseract OCR is not installed | `TEXT_EXTRACTION` evidence, `availability="unavailable"`, `points=0`, reason names the missing dependency |
| File is corrupt or unreadable | `TEXT_EXTRACTION` evidence, `availability="unavailable"`, `points=0` |

A `LOW` band on a document whose text could not be extracted does **not** mean the document is safe — it means nothing could be checked. This is surfaced to the user via `explanation.uncertainty`.

### Error responses

| HTTP status | Meaning |
|---|---|
| 400 | No file provided, or the file is empty |
| 413 | File exceeds the 10 MB limit |
| 415 | Unsupported file type (not PDF/PNG/JPEG) |
| 500 | Unexpected backend error (must not leak stack traces) |

### Scoring category

Document evidence contributes through `Rule_points` (cap 45), per `docs/scoring-engine.md` Section 2. There is no separate document scoring category in v1.

## Gmail integration (Phase 9)

On-demand polling only, no background scheduler. The user explicitly
connects a Gmail account via OAuth, then explicitly triggers a check via
"Check now" in the UI. There is no automatic/scheduled polling in this
phase.

Scope requested: `https://www.googleapis.com/auth/gmail.readonly` only.
SafeCheck never sends, modifies, or deletes email.

### Endpoint: GET /v1/email/status

Whether a Gmail account is currently connected, and when it was last checked.

```json
{
  "connected": true,
  "email_address": "user@gmail.com",
  "last_checked_at": "2026-09-05T10:00:00+00:00"
}
```

If no account is connected: `{"connected": false, "email_address": null, "last_checked_at": null}`.

### Endpoint: POST /v1/email/connect/start

Starts the OAuth flow. Returns a Google consent URL the frontend redirects the user's browser to.

Response:
```json
{ "authorization_url": "https://accounts.google.com/o/oauth2/v2/auth?..." }
```

### Endpoint: GET /v1/email/connect/callback

Google redirects here after the user grants (or denies) consent, with
`code` and `state` query parameters. Exchanges `code` for tokens via
Google's token endpoint, persists the refresh token, then redirects the
browser back to the frontend (`FRONTEND_URL` + `/email?connected=true`,
or `?connected=false&reason=...` on failure/denial).

This endpoint is not meant to be called directly by frontend JS -- it is
the OAuth redirect target, hit by the browser navigating away from
Google.

### Endpoint: POST /v1/email/check-now

Fetches recent messages from the connected Gmail account (up to a fixed
batch size, most recent first) and runs each through the same pipeline as
`POST /v1/check` with `source_type=EMAIL`. Returns one `CheckResponse`
per message, plus the Gmail message id and basic headers so the frontend
can display which email each result belongs to.

Request: empty body.

Response:
```json
{
  "checked_count": 3,
  "results": [
    {
      "message_id": "18c9f2a1b3d4e5f6",
      "from": "support@example.com",
      "subject": "Your account will be suspended",
      "received_at": "2026-09-05T09:55:00+00:00",
      "check": { "...": "same shape as POST /v1/check response" }
    }
  ]
}
```

Error responses:

| Status | Meaning |
|---|---|
| 400 | No Gmail account is connected. Client should call `/v1/email/connect/start` first. |
| 401 | Stored token is invalid/revoked (e.g. user revoked access from their Google account). Client should re-connect. |
| 502 | Gmail API returned an unexpected error. |
